# DB 구성 협의 정리

## 결정된 내용

| 항목 | 내용 |
|---|---|
| 언어·DB | SQL / PostgreSQL |
| 고객사 분리 | 회사별 Silo DB. 회사마다 전용 DB 환경에 같은 테이블 구조를 구성하고 데이터를 분리 |
| 파일 업로드 검사 | 검사 통과 및 파일 등록 후 사용. 검사 작업 테이블 `file_scan_job`은 명세에 반영 |

## 협의가 필요한 내용

| 항목 | 결정할 내용 | 협의 대상 |
|---|---|---|
| AWS DB 서비스 | DEV의 RDS for PostgreSQL 채택 확정 여부. STG·PRD는 RDS 또는 Aurora 선택 | 인프라 |
| DB 버전·사양 | PostgreSQL 세부 버전, 용량, 장애 대비 이중화, 환경별 Silo 구성 | 인프라 |
| 백업·복구·보존 | 백업 주기·보관기간·복구 목표 결정. 업무기록 보존기간은 업무·QA 요구 확인 | 인프라 |
| 문자·시간 | UTF8·UTC 적용 및 화면 표시 시간대 결정 | BE |
| 조직ID | 공장·연구소 등 사업장별 관리가 필요한지 업무 담당자에게 확인한 후 `organization_id` 유지·제거 및 프로젝트 소속 구조 결정 | BE |
| 신규 회사 DB 자동 생성 | 자동화 범위·실행 담당·시점 결정. 인프라는 DB 자원 생성, BE는 테이블·초기 데이터 적용과 서비스 연결 | 인프라·BE |
| 자동 생성 실패 처리 | 완료 확인 후 사용 활성화, 실패 시 복구·재시도 및 중복 생성 방지 방식 결정 | 인프라·BE |
| 회사별 DB 접속 | 회사별 접속정보·계정·Secret 관리와 인증된 회사에 맞는 DB 연결 방식 결정 | 인프라·BE |
| 초기 데이터 | 역할·활동 등 공통 기준정보와 회사별 설정의 초기 등록 범위 결정 | BE |
| DB 변경 관리 | Flyway 또는 팀 표준 도구 선택. SQL 파일의 Git 관리, 실행 시점, 회사별 적용 이력 관리 방식 결정 | BE |
| pgvector | AI 담당과 검색 범위 확인 후 미사용 / pgvector / 별도 벡터 저장소 선택. 채택 시 인프라에서 지원 버전 확인 | BE·인프라 |
| 파일 검사 구현 | 검사 서비스·격리 저장·큐 구성과 검사 결과 반영·사용 차단 방식 결정 | 인프라·BE |
| 비동기 작업 | 파일 검사·AI·PDF 작업의 회사 구분, 중복 처리 방지, 실패·재시도 방식 결정 | BE |
